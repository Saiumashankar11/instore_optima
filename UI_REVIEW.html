InStore Optima · client (React + Vite) · reviewed by area, severity-tagged

High Medium Low

Summary

A well-structured, feature-rich SPA with clean separation of concerns (context providers, a per-resource service layer, shared components, centralized validators). The main weaknesses are zero automated tests, heavy reliance on inline styles, token storage in localStorage, and over-fetching for dashboard/stats. None are architecture-breaking, but they will slow scaling and hurt maintainability.

Key Findings

  • High No test suite anywhere — no unit, component, or integration tests.
  • High JWT stored in localStorage (api/axiosClient.js) — exposed to XSS.
  • Medium Dashboard polls 6 full-table endpoints every 30s just to compute counts.
  • Medium Pervasive inline style objects re-created on every render; no design-token discipline (undefined --surface-2/--border shipped to prod).
  • Medium Very large page components (Messages.jsx ~750 lines, LandingPage.jsx, Profile.jsx).
  • Low 551 kB JS bundle, no code-splitting (Vite warns).

Detailed Review

Components

  • Medium Several pages exceed 400–750 lines, mixing data fetching, form state, and presentation — split into container + presentational pieces.
  • Low Good reuse via shared/ (DataTable, FormModal, StatusBadge, StatusFilter, SearchBar) — keep extending this.
  • Low Inline sub-components (e.g. TH in Orders) re-created each render; hoist them.

State

  • Low Multi-step forms use many useState hooks (Login OTP, Profile) — a useReducer would reduce bugs.
  • Low Server data kept in local component state with manual refetch; consider React Query/SWR for caching, dedupe, and background refresh (replaces hand-rolled polling).
  • Low Context split (Auth/Theme/Messages/AlertBadges) is clean and avoids one mega-store. 👍

Props

  • Low zoom/setZoom drilled through layouts to pages — fine, but a small ZoomContext would be cleaner.
  • Low No PropTypes / TypeScript — prop contracts are implicit.

Performance

  • Medium Dashboard fires 6 getAll* calls every 30s and computes counts client-side — should hit a single summary endpoint.
  • Low No React.memo/useMemo on list rows or derived filters; fine at current data sizes, will matter as tables grow.
  • Low Single 551 kB chunk — add route-level React.lazy + Suspense.

Code Quality

  • Medium Inline styles everywhere — hard to theme/maintain; the undefined CSS-var bug (transparent inputs) was a direct symptom. Prefer CSS classes / tokens.
  • Low Centralized utils/validators.js and per-resource services/ are real strengths — consistent and DRY.
  • Low A few dead bits removed during review (unused replenData); add ESLint no-unused-vars to CI.

Security

  • High Token + user object in localStorage — vulnerable to XSS token theft. Prefer httpOnly cookies, or accept the risk with a strict CSP.
  • Low React escapes JSX by default and no dangerouslySetInnerHTML on user data observed — good.
  • Low Client-side role checks are UX only; ensure the API enforces authorization (it does via [Authorize]).

Accessibility

  • Medium Icon-only buttons (btn-icon) rely on title; add aria-label for screen readers.
  • Medium Status conveyed by color (badges, low-stock red) — add text/icon so it's not color-only.
  • Low Custom modals (FormModal/ContactSupportModal) — verify focus trap, ESC-to-close, and role="dialog"/aria-modal.

Error Handling

  • Low Strong, consistent pattern: try/catch + parseApiError + toast; ErrorBoundary present. 👍
  • Medium A few silent catch {} blocks (Stock.jsx, AuditLogs.jsx) hide failures — at least log/toast.
  • Low parseApiError now surfaces backend messages first (fixed) — good.

API

  • Low Clean axios instance with auth + error interceptors and a per-resource service layer. 👍
  • Medium No request cancellation (AbortController) — fast route changes can set state on unmounted components.
  • Low baseURL:'' relies on the dev proxy; document the prod base URL.

Testing

  • High No tests at all. Start with Vitest + React Testing Library on validators.js, parseApiError, and critical flows (login OTP, order→payment).

Recommendations

  1. Add Vitest + RTL; cover validators, error parsing, and the OTP/payment flows first.
  2. Introduce a single /api/dashboard/summary endpoint; drop the 6-call polling.
  3. Adopt React Query (or SWR) for server state — caching, dedupe, background refresh, cancellation.
  4. Migrate inline styles to CSS classes/tokens; define all CSS variables in one place.
  5. Route-level code-splitting with React.lazy.
  6. Add aria-label to icon buttons; ensure modals trap focus and close on ESC.
  7. Consider httpOnly cookie auth, or add a strict CSP to mitigate localStorage-token XSS.

Strengths

  • Clear layering: contexts, per-resource services, shared components, central validators.
  • Consistent UX patterns — toasts, undo-delete, status badges, confirm modals.
  • Resilient error UX with an ErrorBoundary and a single error-parsing utility.
  • Thoughtful details: theming, live ticker, badge alerts, role-aware navigation.

Final Verdict

Solid B+ codebase. Architecture and feature quality are strong for a project this size; it ships and behaves well. To reach production-grade, prioritize (1) a test suite, (2) auth-token hardening, and (3) replacing ad-hoc data fetching with a cached server-state layer + a summary endpoint. Styling/accessibility cleanup is steady-state work, not blocking.
